### Benchmarks on PRs (Jorge)

Jorge: I've been working on a PR to run benchmarks on every PR in CI to catch performance regressions earlier. Benchmarks on CI take a long time. The PR adds a tool called `hyperlight-ci`, which runs the benchmarks in parallel: 8 CPUs run 8 benchmarks in parallel. That lets us reduce the benchmark time significantly. It also uses Criterion. One issue is that the benchmark results are quite unstable. With KVM, going from 0 to 1 VM is very expensive. When running a benchmark, it amortizes this cost by bringing up 1 VM first. When we specify runners in Azure, we may get different CPUs. Adding a large margin for regressions and improvements is the current workaround. The tool posts a comment on a PR. Let me know what you think about the comments; I would like to get it merged. We had to increase artifact retention from 5 days to 90 days.

Simon: I seem to recall that we kept retention at 5 days because we ran out of storage. We may want to try to increase that. We may have been in Deis Labs at the time; we might want to try again now and see whether we can retain artifacts longer.

Jorge: Maybe we can store less data if we need to, or store data elsewhere.

James: Let's move quickly on this and see whether it's useful.

Jorge: Agreed. It doesn't change behavior; it's additive only.

### Native host functions (Jorge)

Jorge: Instead of using a custom binary for the surrogate process, we could consider forking early in the process and using that fork as the surrogate. We have some experience doing this (see [zygote](https://docs.rs/zygote/latest/zygote/) and [runwasi](https://github.com/containerd/runwasi/blob/f1401719a3e981956ced9cd685abb2a49190bd1c/crates/containerd-shimkit/src/sandbox/cli.rs#L202)).
- Lucy: I don't think performance is sensitive here and that approach makes support for fork-less platforms difficult.
- Simon: We might need to think about how snapshots work with this. Right now, I think we capture (and maybe validate on restore) metadata about host functions. If these host functions are expected to be provided in a specific binary, then we might want to capture that binary (not process state) in the snapshot.
