### Benchmarks on PRs (Jorge)

Jorge: I've been working on a PR to run benchmarks on every PR on CI to catch perf regressions earlier. Benches on CI take a long time. Adds a tool called `hyperlight-ci` which runs the benchmarks in parallel, 8 cpus -> 8 benches in parallel. That lets us reduce the bench time by a lot. Also uses criterion. One issue is that the bench results are quite unstable. With KVM going from 0 -> 1 VM is very expensive. When it runs a bench it amortizes this cost by bringing up 1 VM first. When we specify runners in Azure we may get different CPUs. Adding a huge margin for regressions/improvements is the current work-around. The tool posts a comment on a PR. Let me know what you think about the comments. Would like to get it merged. We had to bump artifact retention time 5 days -> 90 days.

Simon: I seem to recall that we kept 5 days because we ran out of storage. We may want to try and increase that. We may have been in Deis labs at the time; might want to try again now and see whether we can retain that now.

Jorge: Maybe we can store less data if we need to. or state data elsewhere

James: let's move quickly on this and see whether it's useful. let's go quickly.

Jorge: agreed - doesn't change behavior, additive only.

### Native host functions (Jorge)

Jorge: We could consider instead of a custom binary for the surrogate process, forking early on in the process, and using that fork as the surrogate. We have some experience doing things like this (see [zygote](https://docs.rs/zygote/latest/zygote/) and [runwasi](https://github.com/containerd/runwasi/blob/f1401719a3e981956ced9cd685abb2a49190bd1c/crates/containerd-shimkit/src/sandbox/cli.rs#L202))
- Lucy: I don't think performance is sensitive here and that approach makes support for fork-less platforms difficult.
- Simon: we might need to think about how snapshots work with this, right now (I think) we capture (and maybe validate on restore) metadata about host functions, if these host functions are expected to be provided in a specific binary then we might want to capture that binary (not process state) in the sanpshot
