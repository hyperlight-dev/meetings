## hyperlight — Use talc as the guest heap allocator ([#1928](https://github.com/hyperlight-dev/hyperlight/pull/1928))

Ludvig: we use buddy system allocator in HL guest. I found switching the allocator gives us improved perf. The one we're using right now doesn't seem that good.

Lucy: does this still have a perf improvement after the changes made?

Ludvig: yes, but requires kernel 6.18. Probably because it writes less heap on startup

Lucy: I think the last time we talked about this we concluded we should use a security hardened allocator if at all possible (semalloc, etc). Could we look at that as an option? We can use it now, not before

Ludvig: good point to look at those. I will look at that.

Simon: memolloc?

Lucy: semalloc is the other MSFT one we want

Tomasz: mimalloc has landed necessary fixes. memalloc is used in wasm, potentially good fix for us.

Ludvig: mimalloc for Rust requires picolibc -> compilation time. This PR is the last one in a stack for the layered snapshots. not too important right now.

Tomasz: this PR is very straight forward replacement. small diff. it's a win; other allocators are not a drop-in replacement.

Lucy: true

Ludvig: merge this one after the other PRs, see if we can switch them out later

Lucy: for the comment tomasz made in the PR: the interrupt handler should really not be allocating.

Tomasz: ah ok

Lucy: the handler causes CoW - don't want a CoW-fault
